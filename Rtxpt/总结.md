# NVIDIA RTX Path Tracing (RTXPT) v1.8.1 项目全景梳理

---

## 一、项目总览

RTXPT 是 NVIDIA 发布的开源 DXR 路径追踪 SDK，展示了以物理为基础的实时/离线光追渲染的完整工程方案。

| 项目 | 内容 |
|------|------|
| **渲染 API** | NVRHI（DX12/Vulkan 抽象层） |
| **框架** | Donut（NVIDIA 内部渲染框架） |
| **Shader** | HLSL + DXR |
| **模式** | Realtime（实时+降噪）/ Reference（逐帧累积参考） |
| **集成技术** | RTXDI、NRD、DLSS/DLSS-G/DLSS-RR、SER、OMM |

## 三、主渲染管线流程（Realtime 模式）

```
每帧 Sample::Render()
│
├─ StreamlinePreRender()          → 配置 Reflex 低延迟、DLSS/DLSS-G 参数、DLSS 分辨率
│
├─ 场景更新
│   ├─ BLAS 更新（蒙皮重建）
│   ├─ TLAS 构建
│   └─ 材质更新 (MaterialsBaker)
│
├─ PreUpdateLighting()            → EnvMap Cubemap 更新 + 重要性图烘焙
├─ RtxdiSetupFrame()              → RTXDI 资源准备、灯光列表设定
├─ UpdateLighting()               → LightsBaker (analytic + emissive + env 灯光)
│
├─ SampleRenderCode()
│   └─ PathTrace()
│       ├─ [Pass 1] BuildStablePlanes (RT)
│       │   └─ Whitted-style delta路径，建立 StablePlane 结构体系
│       │   → 输出: StablePlanesBuffer, Depth, MotionVectors, Throughput, SpecularHitT
│       │
│       ├─ [Pass 2] VBufferExport (Compute)
│       │   └─ StablePlanes 主表面 → 紧凑 SurfaceDataBuffer（供 RTXDI 使用）
│       │
│       ├─ LightsBaker::UpdateEnd()   → 最终光源代理数据上传
│       │
│       ├─ [Pass 3] FillStablePlanes (RT)  ← Realtime / 含噪声漫反射路径追踪
│       │   └─ 向各 StablePlane 的端点追踪 noisy diffuse 路径，沉积辐射
│       │   → 输出: OutputColor, DenoiserDiffRadiance, DenoiserSpecRadiance
│       │   （可循环 subSampleIndex 次实现 N spp）
│       │
│       ├─ [Pass 4] RTXDI (可选)
│       │   ├─ ReSTIR DI → 直接光重要性重采样，结果追加到 OutputColor
│       │   ├─ ReSTIR GI → 间接光二次弹射重采样
│       │   └─ (可选) FusedDIGIFinal → 合并 DI+GI 最终着色
│       │
│       └─ [Pass 5] DenoisingGuidesBaker (Compute)
│           ├─ DenoiseSpecHitT    → 处理 SpecularHitT 缓冲
│           └─ ComputeAvgLayerRadiance → 计算各 StablePlane 平均辐射
│
├─ Denoise()                      → NRD 降噪（每 StablePlane 独立一个 ReLAX/ReBLUR 实例）
│
├─ PostProcessAA()                → TAA / DLSS / DLSS-RR
│   OutputColor → ProcessedOutputColor
│
├─ PostProcessPreToneMapping()    → HDR 后处理（Bloom），写入 ProcessedOutputColor
├─ ToneMappingPass                → ProcessedOutputColor → LdrColor
├─ PostProcessPostToneMapping()   → LDR 后处理（EdgeDetection 等）
├─ ShaderDebug::EndFrameAndOutput → 调试叠加层
└─ BlitTexture                    → LdrColor → 交换链
```

**Reference 模式**差异：跳过 StablePlanes，直接运行 `m_ptPipelineReference`，每帧结果通过 `AccumulationPass` 累积到 `AccumulatedRadiance`，无 NRD/TAA。

## 六、StablePlanes 系统——核心设计

这是整个项目最重要的创新点，解决了路径追踪降噪的核心难题：

**问题**：包含多次镜面反射的像素，其漫反射噪声和镜面路径混在一起，NRD 无法有效降噪，且镜面反射路径的运动模式与漫反射不同，导致时序错误。

**方案**：

```
BuildStablePlanes Pass（Whitted-style，无噪声）
  ↓ 追踪 delta 路径（完美反射/折射链），拆解每像素为最多3层"稳定平面"
  每层记录: 路径端点位置、法线、roughness、throughput、delta路径的运动向量

FillStablePlanes Pass（含噪声路径追踪）
  ↓ 从每层稳定平面端点出发，追踪含噪声的漫反射子路径，结果沉积到该平面

NRD 降噪（每 StablePlane 独立一个 NRD 实例）
  ↓ 利用各层独立的运动向量精细降噪

合成：去噪 StablePlane[0..2] + StableRadiance（无噪声 delta 贡献）→ OutputColor
```

**效果**：镜子里的漫反射区域有自己的运动向量和降噪估计，质量远好于将所有噪声混在一起降噪。

## 七、RT 管线变体

| 管线 | Shader | 模式宏 | 用途 |
|------|--------|--------|------|
| `m_ptPipelineBuildStablePlanes` | PathTracerSample.hlsl | `MODE_BUILD_STABLE_PLANES` | StablePlanes 构建 |
| `m_ptPipelineFillStablePlanes` | PathTracerSample.hlsl | `MODE_FILL_STABLE_PLANES` | 向 StablePlanes 填充噪声辐射 |
| `m_ptPipelineReference` | PathTracerSample.hlsl | `MODE_REFERENCE` | Reference 模式标准 PT |
| `m_ptPipelineTestRaygenPPHDR` | TestRaygenPP.hlsl | `PP_TEST_HDR` | HDR 后处理测试通道 |
| `m_ptPipelineEdgeDetection` | TestRaygenPP.hlsl | `PP_EDGE_DETECTION` | LDR 边缘检测后处理 |

5个管线全部来自同一套 Shader，**通过宏区分行为**，底层 Hit/Miss shader 也共用。

## 八、建立直觉的关键认知

1. **Realtime 模式 = 两次 RT，不是一次**
   BuildStablePlanes（精确 delta 链）+ FillStablePlanes（含噪声漫反射）。这不是优化手段，而是降噪策略的基础。

2. **StableRadiance 存储完全无噪声的贡献**
   delta 路径（完美镜面/折射）上的直接光/发光材质贡献可以精确计算，不需要降噪，直接放入 `StableRadiance`。

3. **SurfaceDataBuffer 是 RTXDI 的入口**
   VBufferExport Compute Pass 把 StablePlane[0] 的主表面数据导出，RTXDI 才能知道"应该为哪些表面采样光源"。

4. **DLSS-RR 需要辐射分解（albedo demodulation）**
   DLSS-RR 需要 DiffAlbedo + SpecAlbedo 才能正确重建。路径追踪器在 FillStablePlanes 时同时写入 `RRDiffuseAlbedo` 等缓冲区。

5. **全局 Binding Layout 是共享的**
   所有 Pass（RT、Compute、光栅）使用同一个 `m_bindingLayout`/`m_bindingSet`。这极大简化了多 Pass 间资源传递，代价是 Binding Set 很大（约80+个 slot）。

6. **SubSampleIndex 循环实现多 spp**
   `FillStablePlanes` 通过 `for (subSampleIndex < ActualSamplesPerPixel())` 循环，每次 `dispatchRays` 对应一个 sample，miniConstants.x 传递 subSampleIndex 作为随机数种子区分。

7. **NEE 与 RTXDI 是互斥的增强手段**
   NEE（Next Event Estimation）是经典直接光采样。RTXDI 是时序重采样的强化版，复杂光照场景下更高效。两者都通过宏开关控制，运行时可切换。
